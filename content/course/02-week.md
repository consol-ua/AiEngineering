# Тиждень 2. Model Selection, Embeddings та Local Inference

## Урок 5. Типи мовних моделей

### 5.1. Base Models vs Instruct Models

Base model навчається передбачати продовження тексту. Вона може добре моделювати мову, але не обов'язково надійно виконуватиме інструкції користувача.

Instruct model проходить додаткове навчання для виконання інструкцій і ведення діалогу. Воно може включати supervised fine-tuning та різні методи preference optimization.

Для AI-асистента зазвичай варто починати з instruct-моделі.

### 5.2. Encoder, Decoder та Encoder-Decoder

| Архітектура     | Типове використання                        |
| --------------- | ------------------------------------------ |
| Encoder-only    | Класифікація, embeddings, розуміння тексту |
| Decoder-only    | Генерація тексту, чат, tool calling        |
| Encoder-decoder | Переклад, підсумовування, text-to-text     |

Ці категорії описують архітектуру, але конкретні можливості залежать від навчання моделі.

### 5.3. Open-weight vs Hosted Models

Open-weight models дозволяють отримати ваги моделі відповідно до умов її ліцензії. Це не завжди означає повністю open-source модель.

Hosted models доступні через API провайдера, який керує інфраструктурою inference.

| Критерій                | Локальна модель           | Hosted API                      |
| ----------------------- | ------------------------- | ------------------------------- |
| Початкове налаштування  | Складніше                 | Простіше                        |
| Контроль інфраструктури | Вищий                     | Нижчий                          |
| Масштабування           | Власна відповідальність   | Значною мірою провайдера        |
| Витрати                 | Обчислювальні ресурси     | Тарифікація сервісу             |
| Приватність             | Залежить від конфігурації | Залежить від політик провайдера |
| Оновлення моделі        | Під твоїм контролем       | Може залежати від провайдера    |

## Урок 6. Embeddings і Vector Representations

Embedding — це числове представлення даних, яке дозволяє математично порівнювати об'єкти.

Наприклад:

```
"Python is a programming language"
             ↓
[0.12, -0.48, 0.73, ...]
```

Вектор може мати сотні або тисячі компонентів.

Для semantic search важливо, щоб модель була навчена зближувати семантично пов'язані тексти у векторному просторі.

### Cosine Similarity

```formula
cos(θ) = (A·B) / (‖A‖ × ‖B‖)
```

Якщо вектори нормалізовані до одиничної довжини, cosine similarity дорівнює їхньому скалярному добутку.

Best practices:

- Використовуй embedding-модель, придатну для мов твоїх документів.
- Перевіряй якість на реальних пошукових запитах.
- Не змішуй вектори несумісних embedding-моделей в одному індексі.
- Зберігай назву та версію embedding-моделі.
- Не трактуй similarity score як абсолютну ймовірність релевантності.

На цьому етапі достатньо зрозуміти концепцію. Повноцінний vector search реалізовуватимемо в модулі 2.

## Урок 7. Quantization та оптимізація локальних моделей

### 7.1. Навіщо потрібна quantization

Ваги нейронних мереж займають пам'ять. Спрощено, для моделі із 7 мільярдами параметрів:

| Представлення | Теоретичний розмір ваг |
| ------------- | ---------------------- |
| FP32          | 28 GB                  |
| FP16          | 14 GB                  |
| INT8          | 7 GB                   |
| 4-bit         | 3,5 GB                 |

Це лише розмір ваг без metadata, KV cache, runtime overhead та інших компонентів.

Quantization зменшує точність представлення ваг і може дозволити запускати більші моделі на доступному обладнанні.

### 7.2. Основні компроміси

Quantization може впливати на:

- Якість відповідей.
- Швидкість генерації.
- Використання пам'яті.
- Стабільність structured outputs.
- Підтримку конкретного inference runtime.

Не можна припускати, що 4-бітна модель обов'язково працюватиме швидше за 8-бітну на будь-якому пристрої.

## Урок 8. Ollama та локальний inference

Ollama дозволяє запускати підтримувані моделі локально та працювати з ними через HTTP API.

Встановлення: [Ollama Download](https://ollama.com/download).

```

# Завантаження моделі
ollama pull llama3.2:3b

# Інтерактивний запуск
ollama run llama3.2:3b

# Список завантажених моделей
ollama list

```

Приклад Python-клієнта:

```python
import httpx

async def ask_local_llm(prompt: str) -> str:
    async with httpx.AsyncClient(timeout=60.0) as client:
        response = await client.post(
            "http://localhost:11434/api/generate",
            json={"model": "llama3.2:3b", "prompt": prompt, "stream": False},
        )
        response.raise_for_status()
        return response.json()["response"]
```

### Best Practices для локального inference

Вибір моделі: починай з невеликої instruct-моделі та перевіряй її на конкретних задачах.

Версіонування: зберігай точний ідентифікатор і digest моделі, якщо потрібна відтворюваність.

Ізоляція: не відкривай локальний inference API в публічний інтернет без належного захисту.

Ресурси: контролюй RAM/VRAM, CPU/GPU utilization та concurrency.

Benchmark: окремо вимірюй cold start, TTFT, tokens/sec та end-to-end latency.
