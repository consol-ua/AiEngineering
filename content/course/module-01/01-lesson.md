## Урок 1. Що таке AI Engineering

### 1.1. Визначення та роль AI Engineer

AI Engineering — це розробка програмних систем, у яких AI-моделі інтегровані в бізнес-логіку, взаємодіють із даними, інструментами й користувачами та працюють із визначеними вимогами до якості, швидкості, вартості й безпеки.

AI Engineer не обов'язково навчає власну нейронну мережу. Значна частина роботи полягає в тому, щоб ефективно використовувати вже навчені моделі.

Наприклад, уявімо систему, яка відповідає на запитання про внутрішню документацію компанії.

Звичайна інтеграція LLM:

`User → Prompt → LLM → Answer`

AI Engineering підхід:

`User → Authentication → Query Processing → Retrieval → Context Assembly → LLM → Validation → Response`

Паралельно працюють логування, моніторинг, контроль витрат, безпека та оцінювання якості.

### 1.2. AI Engineer vs ML Engineer vs Backend Engineer

| Напрям           | Основний фокус                                           |
| ---------------- | -------------------------------------------------------- |
| Backend Engineer | API, бізнес-логіка, бази даних, надійність               |
| ML Engineer      | Моделі, навчання, inference infrastructure               |
| AI Engineer      | LLM, контекст, retrieval, агенти, evaluation, інтеграція |

Ролі перетинаються. Сильному AI Engineer потрібні навички backend engineering, але також розуміння недетермінованої поведінки моделей.

### 1.3. Чому LLM-системи складніші за звичайний API

У класичному API часто існує чіткий контракт:

```python
def add(a: int, b: int) -> int:
    return a + b
```

Для однакових вхідних значень результат однаковий.

LLM API працює інакше: відповідь формується на основі ймовірнісного розподілу токенів. Навіть за однакового запиту результат може змінюватися.

Тому в AI Engineering важливо розрізняти:

- Software correctness: чи правильно працює код.
- Model quality: наскільки добре модель виконує завдання.
- System reliability: чи стабільно працює весь pipeline.
- Safety: чи не створює система неприйнятних ризиків.
- Cost efficiency: скільки коштує успішно виконане завдання.

### Engineering Best Practices

1. Починай із вимірюваної задачі. Не «створити AI-асистента», а «відповідати на запитання про документацію з точністю, прийнятною для визначених сценаріїв».

2. Спочатку створюй baseline. Реалізуй найпростішу версію, а потім додавай складніші компоненти лише за потреби.

3. Відокремлюй LLM від бізнес-логіки. Модель не повинна самостійно вирішувати, чи має користувач право виконати певну операцію.

4. Проєктуй систему так, щоб модель можна було замінити. Не прив'язуй усю архітектуру до одного API.

5. Вимірюй end-to-end результат. Якість окремої моделі не дорівнює якості продукту.

### Антипатерни

- Починати з multi-agent architecture для простої задачі.
- Вважати, що хороший промпт замінює тестування.
- Використовувати LLM там, де достатньо звичайної функції.
- Не передбачати fallback або обробку помилок провайдера.
- Зберігати секрети в коді.
