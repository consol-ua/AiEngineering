## Урок 2. Як працює Large Language Model

### 2.1. Авторегресивна генерація

Більшість сучасних текстових генеративних LLM використовують авторегресивний принцип: модель передбачає наступний токен на основі попереднього контексту.

Математично:

```formula
P(x₁,…,xₙ) = ∏ₜ₌₁ⁿ P(xₜ | x<ₜ)
```

Це означає, що генерація тексту відбувається послідовно.

Наприклад:

`Python is a → programming → language`

На кожному кроці модель обчислює розподіл імовірностей можливих наступних токенів.

Важливий нюанс: токен — не обов'язково слово. Це може бути частина слова, символ або послідовність символів.

### 2.2. Tokenization

Tokenization перетворює текст на послідовність числових ідентифікаторів.

УМОВНИЙ ПРИКЛАД TOKENIZATION

"Artificial intelligence"

Artificial

intelligence

Token IDs → Embedding vectors

Реальне розбиття залежить від tokenizer конкретної моделі.

Чому це важливо:

- API часто тарифікуються за токенами.
- Context window вимірюється в токенах.
- Довгі промпти збільшують витрати й latency.
- Український та англійський тексти можуть мати різну token efficiency.
- Tokenizer однієї моделі не можна автоматично використовувати для точного підрахунку токенів іншої.

### 2.3. Training vs Inference

Training — процес зміни параметрів моделі на основі навчальних даних.

Inference — використання вже навченої моделі для генерації відповіді.

Під час звичайного API-виклику модель не оновлює свої ваги від твоєї розмови.

Це важливо для архітектури: якщо потрібно надати моделі актуальні знання, зазвичай використовують retrieval, інструменти або інші механізми контексту, а не очікують, що вона «запам'ятає» нову інформацію у своїх вагах.

### 2.4. Hallucinations

Hallucination — це згенерована інформація, яка є фактично неправильною, вигаданою або не підтверджується доступними джерелами.

Причини можуть включати:

- Відсутність необхідних знань у контексті.
- Неоднозначність запиту.
- Невідповідні навчальні дані.
- Неправильно підібраний контекст.
- Схильність моделі генерувати правдоподібну відповідь навіть за недостатності інформації.

Best practices для зменшення hallucinations:

- Надавай релевантний перевірений контекст.
- Дозволяй моделі повідомляти про відсутність відповіді.
- Перевіряй факти через незалежні джерела.
- Використовуй structured outputs, коли потрібен контракт даних.
- Створюй evaluation dataset із питаннями, на які немає відповіді.
- Не плутай впевнене формулювання з достовірністю.
