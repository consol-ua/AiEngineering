## Урок 3. Transformer та Attention

### 3.1. Чому Transformer став основою LLM

До Transformer широко використовували рекурентні архітектури, зокрема RNN та LSTM.

Transformer запропонував attention-механізми, які дозволили ефективніше моделювати залежності між токенами та краще паралелізувати обробку послідовностей під час навчання.

Класична стаття:

[Attention Is All You Need — Vaswani et al., 2017](https://arxiv.org/abs/1706.03762)

### 3.2. Query, Key, Value

Кожен токен у Transformer перетворюється на кілька представлень:

- Query (Q): яку інформацію шукає поточна позиція.
- Key (K): за якими ознаками інші позиції можуть бути релевантними.
- Value (V): яку інформацію вони передають.

Attention обчислює ваги взаємодії між позиціями й використовує їх для агрегування інформації.

```formula
Attention(Q,K,V) = softmax(QKᵀ / √dₖ)V
```

Це не пошук у базі даних, а математична операція над векторними представленнями.

### 3.3. Multi-head Attention

У Multi-head Attention декілька attention-голів працюють із різними навченими проєкціями представлень.

Це дозволяє моделі одночасно моделювати різні типи залежностей між токенами.

### 3.4. Causal Attention

У генеративних decoder-only моделях застосовується causal mask, яка не дозволяє позиції використовувати майбутні токени під час передбачення наступного.

### 3.5. KV Cache

Під час авторегресивної генерації модель багаторазово використовує попередній контекст.

KV cache зберігає key/value представлення попередніх токенів, щоб не обчислювати їх заново на кожному кроці.

Це прискорює генерацію, але споживає додаткову пам'ять.

Звідси важливий production-компроміс: довгий контекст може збільшувати використання пам'яті та знижувати доступну concurrency.

### Best Practices

- Розумій різницю між prefill і decode фазами inference.
- Враховуй KV cache при оцінюванні VRAM.
- Не припускай, що збільшення context window автоматично покращує якість.
- Тестуй довгі контексти окремо від коротких.
- Не використовуй attention weights як гарантоване пояснення рішення моделі.
