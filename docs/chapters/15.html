Запуск для користувачів і перевірка швидкості

Після цього розділу ви зможете

Підготувати повторюваний запуск, перевірити перезапуск і виміряти відповіді.

На ноутбуці програма працює, але колега не знає бібліотек і команд. Deployment — розгортання в іншому середовищі. Docker збирає програму із залежностями у контейнер. Нові дані не зберігаються назавжди автоматично: для бази підключіть окрему папку або зовнішнє сховище.

Вам достатньо базового Python: функцій, списків, словників та винятків. Працюємо над одним помічником для інструкцій команди. Спочатку прочитайте приклад, потім запустіть маленький код, після цього виконайте власне завдання. Незрозуміле слово шукайте на сторінці «Нові слова простими словами».

Як це працює на прикладі

/health показує, що процес відповідає. Він не доводить, що пошук і модель працюють. Окремо перевірте /ask із відомим очікуванням. Створіть документ, перезапустіть контейнер і прочитайте знову. Резервну копію теж перевірте відновленням у нову папку.

Середній час приховує кілька дуже повільних відповідей. p95 показує час, якого не перевищують приблизно 95% вимірів. Поряд рахуйте помилки: швидка відмова всім не є корисною швидкістю. Навантажувальний тест — багато реальних запитів, щоб побачити черги й одночасну роботу.

Середовище програми з залежностями для повторюваного запуску.

Окреме сховище даних поза тимчасовим шаром контейнера.

Розрахунок крок за кроком

p95: відсортуйте N часів і візьміть позицію ceil(0,95 × N), починаючи з 1.

Для часів 1..20 секунд позиція ceil(0,95×20)=19, отже p95=19 секунд. На малих наборах способи підрахунку відрізняються; наш код використовує саме цей. Це навчальні числа, не оцінка швидкості вашого сервера.

Спробуйте змінити одне число

Повторіть розрахунок на аркуші або в Python. Спочатку передбачте результат, потім перевірте. Важливо розуміти, що саме вимірює число: схожість, правильність, пам’ять чи час. Не всі ці показники можна порівнювати між собою.

Завантажити 15.py — код і перевірки ↓

Збережіть файл у новій папці. Приклад працює на Python 3.12+ зі стандартною бібліотекою, без платних сервісів. Нижче його основна частина; спочатку розберемо, що роблять функції.

"""Run: python 15.py. Nearest-rank percentiles, failures remain visible."""
import math
import unittest

def percentile(values, p):
    if not values or not 0 < p <= 1 or any(not math.isfinite(x) or x < 0 for x in values):
        raise ValueError('Valid samples and percentile required')
    ordered = sorted(values)
    return ordered[math.ceil(p*len(ordered))-1]

def report(success_latencies, failures):
    if type(failures) is not int or failures < 0:
        raise ValueError('Invalid failures')
    total = len(success_latencies) + failures
    if not total:
        raise ValueError('No requests executed')
    return {'total': total, 'failures': failures,
            'completion_rate': len(success_latencies)/total,
            'p95_success_only': percentile(success_latencies, 0.95) if success_latencies else None}

Що тут відбувається

  • percentile() спочатку сортує виміри.
  • Два успіхи й два збої: 4 спроби, завершено 50%.
  • p95_success_only описує лише успішні відповіді; збої показані окремо, щоб не зникали.

Маленький запуск із відомим результатом

Створіть demo.py у тій самій папці, де лежить 15.py. Скопіюйте наступний код і виконайте python demo.py. runpy.run_path() завантажує функції зі збереженого файла; ви не повинні переписувати їх вручну.

import runpy
m = runpy.run_path("15.py")
print(m["percentile"](list(range(1, 21)), 0.95))
r = m["report"]([1, 2], failures=2)
print(r["total"], r["completion_rate"])

Очікуваний результат

19
4 0.5

Змініть і перевірте

Передайте report([], failures=3). Час успішних відповідей має бути None, а не вигадане швидке число.

Перевірки та обробка помилок

У завантаженому файлі вже є перевірки. Виконайте python 15.py з його папки. Наприкінці має бути OK. Це означає, що перевірки прикладу пройшли, а не що весь майбутній помічник готовий.

class Tests(unittest.TestCase):
    def test_percentile(self):
        self.assertEqual(percentile(list(range(1, 21)), 0.95), 19)
        self.assertEqual(percentile([3], 0.5), 3)
    def test_failure_accounting(self):
        self.assertEqual(report([1, 2], 2)['completion_rate'], 0.5)
        self.assertIsNone(report([], 3)['p95_success_only'])
        with self.assertRaises(ValueError):
            report([], 0)
        with self.assertRaises(ValueError):
            percentile([], 0.95)

if __name__ == '__main__':
    unittest.main()

assertEqual перевіряє рівність, assertTrue — істинність умови, assertRaises — очікувану помилку. Якщо перевірка не пройшла, прочитайте очікуване й отримане значення. Помилка на неправильному вводі часто є саме потрібною поведінкою.

Підміна зовнішнього сервісу перевіряє ваш код без мережі. Якість справжньої моделі, роботу зовнішньої бази та швидкість на вашому обладнанні перевіряють окремо. У FastAPI перетворюйте очікувані помилки на зрозумілу відповідь користувачу.

Практика: зробіть самостійно

Запустіть помічника повторювано та перевірте невелике навантаження.

Кроки завдання

  1. Створіть Dockerfile, README й шлях бази.
  2. Додайте документ і перевірте після перезапуску.
  3. Виконайте 20 /ask із підміною моделі: по одному, потім по 5 одночасно.

Як перевірити свою роботу

Що перевірити кодом

  • p95 для 1..20 дорівнює 19.
  • Нуль вимірів не є успіхом.
  • Дані зберігаються й відновлюються.

Що перевірити своїми очима

  • Запуск без прихованих ручних кроків.
  • Виміряний /ask.
  • Відомо, де зберігається база.
