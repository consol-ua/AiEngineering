RAG: відповіді з ваших документів

Після цього розділу ви зможете

Зібрати відповідь із джерелом і чесну відмову, коли потрібного тексту немає.

RAG означає retrieval-augmented generation — генерація з доданими результатами пошуку. Для питання VPN спочатку знаходимо інструкцію, потім передаємо її моделі разом із питанням. Це відповідь із відкритою книгою: джерело під рукою, але прочитати його все одно треба правильно.

Вам достатньо базового Python: функцій, списків, словників та винятків. Працюємо над одним помічником для інструкцій команди. Спочатку прочитайте приклад, потім запустіть маленький код, після цього виконайте власне завдання. Незрозуміле слово шукайте на сторінці «Нові слова простими словами».

Як це працює на прикладі

Довгі документи розбивають на chunks — фрагменти з текстом, id та джерелом. Пошук обирає кілька, а модель формулює відповідь на їхній основі. Якщо інформації немає, краще сказати «Не знайшов відповіді у документах». Найближчий результат сам по собі не гарантує, що він містить потрібний факт.

Перевірте, що id цитати є серед знайдених фрагментів. Потім прочитайте сам текст: справжня цитата теж може не підтверджувати висновок. Наш respond() просто повертає знайдені уривки. Тут ще немає виклику моделі або автоматичного рішення, чи уривок справді відповідає на питання.

Нові слова простими словами

Retrieval
Пошук документів до формування відповіді.
Chunk
Фрагмент документа з власним id.
Context builder
Функція, що збирає інструкцію, питання й уривки для моделі.
Цитата
Посилання на джерело факту. Існування джерела та підтвердження факту — окремі перевірки.

Розрахунок крок за кроком

Відповідь із джерелом = знайти текст → передати моделі → перевірити факти й цитати.

Джерело каже «VPN потребує другого фактора». Відповідь «Так, потрібен» підтверджена. Відповідь «Ні» хибна, навіть із посиланням на це реальне джерело. Перевірка id не замінює читання.

Спробуйте змінити одне число

Повторіть розрахунок на аркуші або в Python. Спочатку передбачте результат, потім перевірте. Важливо розуміти, що саме вимірює число: схожість, правильність, пам’ять чи час. Не всі ці показники можна порівнювати між собою.

Завантажити 08.py — код і перевірки ↓

Збережіть файл у новій папці. Приклад працює на Python 3.12+ зі стандартною бібліотекою, без платних сервісів. Нижче його основна частина; спочатку розберемо, що роблять функції.

"""Run: python 08.py. Extractive evidence baseline, not generated RAG."""
import unittest

def chunks(text, source, size=100):
    if size < 1:
        raise ValueError('Positive size required')
    return [{'id': f'{source}:{start}', 'source': source, 'text': text[start:start+size]} for start in range(0, len(text), size)]

def respond(hits):
    if not hits:
        return {'answer': None, 'sources': [], 'refusal_reason': 'no_evidence'}
    return {'answer': '\n'.join(hit['text'] for hit in hits), 'sources': [hit['id'] for hit in hits], 'refusal_reason': None}

def validate_citations(cited_ids, hits):
    allowed = {hit['id'] for hit in hits}
    if not set(cited_ids) <= allowed:
        raise ValueError('Invented citation')
    return True

Що тут відбувається

  • chunks() ріже за символами, а не за абзацами чи токенами. Це простий навчальний початок.
  • respond() лише з’єднує передані тексти, він не виконує пошук.
  • no_evidence означає «немає підтвердження». Для користувача перекладіть зрозумілим реченням.

Маленький запуск із відомим результатом

Створіть demo.py у тій самій папці, де лежить 08.py. Скопіюйте наступний код і виконайте python demo.py. runpy.run_path() завантажує функції зі збереженого файла; ви не повинні переписувати їх вручну.

import runpy
m = runpy.run_path("08.py")
hits = m["chunks"]("Для VPN потрібен другий фактор.", "vpn.md")
r = m["respond"](hits)
print(r["answer"])
print(r["sources"])
print(m["respond"]([])["refusal_reason"])

Перевірки та обробка помилок

У завантаженому файлі вже є перевірки. Виконайте python 08.py з його папки. Наприкінці має бути OK. Це означає, що перевірки прикладу пройшли, а не що весь майбутній помічник готовий.

class Tests(unittest.TestCase):
    def test_evidence(self):
        hits = chunks('RAG додає документи до контексту.', 'guide', 10)
        result = respond(hits)
        self.assertTrue(validate_citations(result['sources'], hits))
        self.assertEqual(hits, chunks('RAG додає документи до контексту.', 'guide', 10))
        self.assertEqual(''.join(h['text'] for h in hits), 'RAG додає документи до контексту.')
    def test_refusal_and_forgery(self):
        self.assertEqual(respond([])['refusal_reason'], 'no_evidence')
        with self.assertRaises(ValueError):
            validate_citations(['invented'], [])

if __name__ == '__main__':
    unittest.main()

assertEqual перевіряє рівність, assertTrue — істинність умови, assertRaises — очікувану помилку. Якщо перевірка не пройшла, прочитайте очікуване й отримане значення. Помилка на неправильному вводі часто є саме потрібною поведінкою.

Підміна зовнішнього сервісу перевіряє ваш код без мережі. Якість справжньої моделі, роботу зовнішньої бази та швидкість на вашому обладнанні перевіряють окремо. У FastAPI перетворюйте очікувані помилки на зрозумілу відповідь користувачу.

Практика: зробіть самостійно

Зробіть відповідь за власними документами: спочатку цитата, потім за бажанням переказ моделлю.

Кроки завдання

  1. Створіть три Markdown-файли з інструкціями: vpn.md, leave.md і password.md. Використайте вигадані тексти, без справжніх паролів.
  2. Напишіть 6 питань до них і 2 поза їхніми темами.
  3. Розбийте зі сталими id та джерелами.
  4. Підключіть пошук із розділу 6 або простий пошук слів.
  5. Поверніть текст і джерело, а без потрібного тексту — відмову.
  6. За наявності моделі додайте переказ і перевірте кожен факт за цитатою.

Що показати після виконання

  • Документи й уривки.
  • Таблиця 8 питань із джерелами.
  • Приклад відмови.
Почніть із мінімального варіанта. Частини з позначкою «додатково» не потрібні для першого успіху. Якщо зовнішня модель чи обладнання недоступні, виконайте незалежні кроки й запишіть, що саме ще не перевіряли.

Як перевірити свою роботу

Що перевірити кодом

  • Цитати належать переданим уривкам.
  • Порожні результати не породжують вигадку.
  • Незмінний файл дає ті самі id.

Що перевірити своїми очима

  • Джерело підтверджує факт.
  • Зрозуміло, чи текст цитований, чи переказаний.
  • Питання поза базою відхиляється.
