Пошук за змістом: embeddings

Після цього розділу ви зможете

Порівняти пошук слів із пошуком за змістом і перевірити, який документ знайдено.

Олена питає «Як працювати з дому?», а документ називається «Налаштування VPN». Пошук слова «дім» може нічого не знайти. Семантичний пошук, тобто пошук за змістом, намагається знайти близьку тему навіть за іншими словами. Але точний код помилки або номер версії іноді краще знаходиться звичайним пошуком.

Вам достатньо базового Python: функцій, списків, словників та винятків. Працюємо над одним помічником для інструкцій команди. Спочатку прочитайте приклад, потім запустіть маленький код, після цього виконайте власне завдання. Незрозуміле слово шукайте на сторінці «Нові слова простими словами».

Як це працює на прикладі

Embedding — список чисел, який модель створює для тексту. Перетворюємо документи й питання однією сумісною моделлю, а потім порівнюємо вектори способом із розділу 2. Однакова довжина списків не дозволяє змішувати різні моделі: координати можуть означати різні речі.

Перші результати — кандидати, а не гарантовано правильні джерела. Навіть питання поза базою матиме найближчий документ. Перевіряйте пошук на питаннях, де ви заздалегідь знаєте потрібний id. Наш код використовує ручні вектори для розуміння сортування; справжні текстові embeddings додасте окремо.

Нові слова простими словами

Embedding
Числове представлення тексту для порівняння змісту.
Encoder
Модель-перетворювач тексту у вектор, наприклад SentenceTransformer.encode().
Top-k
Перші k результатів. top-3 — три найвищі оцінки.
Recall@k
Частка потрібних документів, знайдена серед перших k.

Не потрібно завчати визначення. Візьміть одне слово й поясніть його на прикладі нашого помічника. Запишіть у нотатках власне речення. Англійську назву залишено, щоб ви впізнали її в документації.

Розрахунок крок за кроком

Recall@k = знайдені потрібні документи / усі відомі потрібні документи.

Потрібні vpn-guide та access-policy. У перших трьох є лише vpn-guide: Recall@3 = 1/2 = 0,5. Якщо є обидва — 1. Для питання без джерела в базі окремо перевіряйте відмову, а не діліть на нуль.

Завантажити 06.py — код і перевірки ↓

Збережіть файл у новій папці. Приклад працює на Python 3.12+ зі стандартною бібліотекою, без платних сервісів. Нижче його основна частина; спочатку розберемо, що роблять функції.

"""Run: python 06.py. Toy vectors test ranking; use a real encoder in lab."""
import math
import unittest

def cosine(a, b):
    if not a or len(a) != len(b) or any(not math.isfinite(x) for x in [*a, *b]):
        raise ValueError('Invalid vectors')
    norm = math.sqrt(sum(x*x for x in a)) * math.sqrt(sum(x*x for x in b))
    if not norm:
        raise ValueError('Zero vector')
    return sum(x*y for x, y in zip(a, b)) / norm

def search(query_vector, documents, k=3):
    if not isinstance(k, int) or k < 1:
        raise ValueError('Positive k required')
    scored = [(doc['id'], cosine(query_vector, doc['vector'])) for doc in documents]
    return sorted(scored, key=lambda hit: (-hit[1], hit[0]))[:k]

Що тут відбувається

  • search() приймає вже готові числа й сам не читає текст.
  • Питання й vpn мають однакові вектори, тому оцінка 1.
  • Документ leave не потрапляє в top-1.

Перевірки та обробка помилок

У завантаженому файлі вже є перевірки. Виконайте python 06.py з його папки. Наприкінці має бути OK. Це означає, що перевірки прикладу пройшли, а не що весь майбутній помічник готовий.

class Tests(unittest.TestCase):
    def test_rank_and_ties(self):
        docs = [{'id': 'b', 'vector': [1, 0]}, {'id': 'a', 'vector': [1, 0]}, {'id': 'c', 'vector': [0, 1]}]
        self.assertEqual([x[0] for x in search([1, 0], docs, 2)], ['a', 'b'])
    def test_dimensions(self):
        with self.assertRaises(ValueError):
            search([1], [{'id': 'a', 'vector': [1, 0]}])
        with self.assertRaises(ValueError):
            search([0], [{'id': 'a', 'vector': [1]}])

if __name__ == '__main__':
    unittest.main()

assertEqual перевіряє рівність, assertTrue — істинність умови, assertRaises — очікувану помилку. Якщо перевірка не пройшла, прочитайте очікуване й отримане значення. Помилка на неправильному вводі часто є саме потрібною поведінкою.

Підміна зовнішнього сервісу перевіряє ваш код без мережі. Якість справжньої моделі, роботу зовнішньої бази та швидкість на вашому обладнанні перевіряють окремо. У FastAPI перетворюйте очікувані помилки на зрозумілу відповідь користувачу.

Як перевірити свою роботу

Що перевірити кодом

  • Вектор [1, 0] знаходить vpn першим.
  • Різна розмірність відхиляється.
  • Кількість результатів не більша за k.

Що перевірити своїми очима

  • Показав успіх і невдачу пошуку.
  • Відрізняю ручні числа від результатів моделі.
  • Не приймаю схожість за підтвердження факту.
