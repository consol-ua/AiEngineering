AI-помічник: з чого почати

Після цього розділу ви зможете

Створити маленького помічника й перевірити шлях від питання до відповіді. Справжня модель поки не потрібна.

Уявіть нову колегу Олену. Вона питає: «Як підключити робочий VPN?» — програму доступу до внутрішньої мережі. Інструкція є, але її важко знайти серед десятків файлів. Наш майбутній помічник знайде текст, пояснить кроки й покаже джерело. Упродовж курсу будемо додавати до нього по одній можливості.

Вам достатньо базового Python: функцій, списків, словників та винятків. Працюємо над одним помічником для інструкцій команди. Спочатку прочитайте приклад, потім запустіть маленький код, після цього виконайте власне завдання. Незрозуміле слово шукайте на сторінці «Нові слова простими словами».

Як це працює на прикладі

AI Engineering — розробка програм зі штучним інтелектом. Перевірку порожнього рядка, збереження даних і права доступу ви пишете звичайним Python. Мовна модель допомагає обробляти й формулювати текст. Не доручайте їй вирішувати, чи можна показати чужий документ: це правило перевіряє ваш код.

Спочатку замінимо модель функцією, яка повертає заготовлений текст. Таку підміну називають fake. Вона дозволяє перевірити роботу програми без мережі, реєстрації та оплати. Fake не розуміє питання, тому успішний тест підміни ще не доводить якість AI.

Нові слова простими словами

LLM — мовна модель
Програма, навчена працювати з текстом. Наприклад, переказати інструкцію. LLM означає large language model — велика мовна модель.
Провайдер
Сервіс або локальна програма, що надає модель. Наш код звертається до нього через generate().
Baseline — базова версія
Найпростіше рішення для порівняння. Наприклад, пошук слова VPN у файлах.
Контракт
Домовленість про формат. У прикладі status описує результат, answer містить текст.

Не потрібно завчати визначення. Візьміть одне слово й поясніть його на прикладі нашого помічника. Запишіть у нотатках власне речення. Англійську назву залишено, щоб ви впізнали її в документації.

Розрахунок крок за кроком

Частка успіху = правильні відповіді / усі перевірені питання.

Правильно відповіли на 8 із 10 питань: 8 / 10 = 0,8, або 80%. Але незручне речення й витік чужого документа — різні помилки. Тому поряд із відсотком записуйте, що саме пішло не так.

Спробуйте змінити одне число

Повторіть розрахунок на аркуші або в Python. Спочатку передбачте результат, потім перевірте. Важливо розуміти, що саме вимірює число: схожість, правильність, пам’ять чи час. Не всі ці показники можна порівнювати між собою.

Як з’єднані частини

Модель можна замінити

ask() перевіряє питання, generate() створює відповідь. Пізніше замінимо підміну моделлю без переписування перевірок.

Пройдіть шлях одного питання

Уявіть питання «Як підключити VPN?». Для кожного блока схеми скажіть: що він отримує, що робить і що передає далі. Потім повторіть для неправильного вводу. Так ви зрозумієте, де виникає помилка, замість шукати її в усьому проєкті одразу.

Корисні звички та їхня ціна

Одна зрозуміла задача

Запишіть: помічник відповідає лише про інструкції нашої команди.

Передбачена відмова

Для питання поза документами заплануйте «Не знайшов відповіді», а не вигадку.

Збережені приклади

Запишіть питання й очікування, щоб повторювати їх після змін.

У кожної зручності є ціна. Додатковий пошук займає час, збереження даних потребує місця, перевірки додають код. Оберіть одну пораду й поясніть, від якої конкретної помилки вона захищає.

Як розібрати помилку

Код: запускаємо та розбираємо

  1. Знайдіть Answer: у ньому status та answer.
  2. Знайдіть FakeProvider.generate(): він додає заготовлений текст до питання.
  3. Прочитайте ask(): перевірка відбувається до виклику провайдера.
  4. Передайте нормальне питання та порожній рядок.
Завантажити 01.py — код і перевірки ↓

Збережіть файл у новій папці. Приклад працює на Python 3.12+ зі стандартною бібліотекою, без платних сервісів. Нижче його основна частина; спочатку розберемо, що роблять функції.

"""Run: python 01.py. Fake provider tests the contract, not LLM quality."""
from dataclasses import dataclass
from typing import Protocol
import unittest

class Provider(Protocol):
    def generate(self, question: str) -> str: ...

@dataclass(frozen=True)
class Answer:
    status: str
    answer: str

class FakeProvider:
    def generate(self, question):
        return 'Відповідь baseline: ' + question

def ask(question: str, provider: Provider) -> Answer:
    if not isinstance(question, str) or not question.strip():
        raise ValueError('Question is required')
    if len(question) > 4000:
        raise ValueError('Question is too long')
    answer = provider.generate(question.strip())
    if not isinstance(answer, str) or not answer.strip():
        raise ValueError('Invalid provider response')
    return Answer('ok', answer)

Що тут відбувається

  • Protocol описує домовленість: провайдер повинен мати generate(). Це не сама модель.
  • strip() прибирає крайні пробіли: питання з самих пробілів стає порожнім.
  • ValueError повідомляє про непридатні дані. На порожньому питанні це очікуваний результат.

Маленький запуск із відомим результатом

Створіть demo.py у тій самій папці, де лежить 01.py. Скопіюйте наступний код і виконайте python demo.py. runpy.run_path() завантажує функції зі збереженого файла; ви не повинні переписувати їх вручну.

import runpy
m = runpy.run_path("01.py")
r = m["ask"]("Як підключити VPN?", m["FakeProvider"]())
print(r.status)
print(r.answer)

Змініть і перевірте

Замініть питання на три пробіли: очікуйте ValueError. Потім змініть лише заготовку FakeProvider і перевірте, що status лишається ok.

Перевірки та обробка помилок

У завантаженому файлі вже є перевірки. Виконайте python 01.py з його папки. Наприкінці має бути OK. Це означає, що перевірки прикладу пройшли, а не що весь майбутній помічник готовий.

class Tests(unittest.TestCase):
    def test_contract(self):
        result = ask('Що таке RAG?', FakeProvider())
        self.assertEqual(result.status, 'ok')
        self.assertIn('RAG', result.answer)
    def test_reject_before_provider(self):
        class Never:
            def generate(self, question):
                raise AssertionError('Must not be called')
        for value in ['', '   ', None, 'a' * 4001]:
            with self.assertRaises(ValueError):
                ask(value, Never())

if __name__ == '__main__':
    unittest.main()

assertEqual перевіряє рівність, assertTrue — істинність умови, assertRaises — очікувану помилку. Якщо перевірка не пройшла, прочитайте очікуване й отримане значення. Помилка на неправильному вводі часто є саме потрібною поведінкою.

Підміна зовнішнього сервісу перевіряє ваш код без мережі. Якість справжньої моделі, роботу зовнішньої бази та швидкість на вашому обладнанні перевіряють окремо. У FastAPI перетворюйте очікувані помилки на зрозумілу відповідь користувачу.

Практика: зробіть самостійно

Перша версія помічника для інструкцій команди. Почніть зі звичайної функції, а FastAPI додайте після її перевірки.

Кроки завдання

  1. Створіть папку й збережіть 01.py.
  2. Напишіть три питання: VPN, відпустка та порожнє; запишіть очікування.
  3. Створіть власну підміну з короткою відповіддю.
  4. Запустіть ask() для трьох питань і збережіть результати.
  5. Додайте POST /ask у FastAPI: прийміть question та поверніть status і answer.
  6. У README зазначте, що справжня модель ще не підключена.

Що показати після виконання

  • Функція й підміна моделі.
  • Таблиця «питання → очікування → результат».
  • README з командою запуску.
Почніть із мінімального варіанта. Частини з позначкою «додатково» не потрібні для першого успіху. Якщо зовнішня модель чи обладнання недоступні, виконайте незалежні кроки й запишіть, що саме ще не перевіряли.

Як перевірити свою роботу

Що перевірити кодом

  • Нормальне питання повертає ok та непорожній текст.
  • Порожній ввід відхиляється до виклику провайдера.
  • Запуск не потребує ключів або мережі.

Що перевірити своїми очима

  • Можу пояснити роль кожної частини.
  • Показав неправильний ввід.
  • Відрізняю підміну від справжньої моделі.

Як зрозуміти, що завдання виконане
