Інструменти й агенти простими словами

Після цього розділу ви зможете

Додати дозволений калькулятор і обмежити назви функцій, аргументи та кроки.

Модель може помилитися в 127 + 386. Інструмент — звичайна функція для конкретної роботи: додавання чи пошуку. Модель пропонує add з числами, ваш код перевіряє дозвіл і виконує обчислення. Відповідь тоді спирається на результат функції.

Вам достатньо базового Python: функцій, списків, словників та винятків. Працюємо над одним помічником для інструкцій команди. Спочатку прочитайте приклад, потім запустіть маленький код, після цього виконайте власне завдання. Незрозуміле слово шукайте на сторінці «Нові слова простими словами».

Як це працює на прикладі

Агент може повторити кілька кроків: обрати дію, прочитати результат, вирішити наступну дію. Для питання про VPN часто вистачить одного пошуку, без складного агента. Додаткові кроки виправдані, якщо допомагають, а не лише роблять програму модною.

Не виконуйте довільний код моделі через eval(). Замість цього створіть словник дозволених функцій. shell або delete_all відхиляються, якщо їх немає у списку. Межа кроків захищає від нескінченного повтору. У прикладі є готові команди, але ще немає планування моделлю.

Нові слова простими словами

Tool
Дозволена функція з відомими аргументами, наприклад add(a, b).
Tool calling
Модель пропонує функцію й дані; ваша програма виконує після перевірки.
Registry
Словник дозволених інструментів на кшталт {"add": add}.
Ліміт кроків
Максимальна кількість дій за одну задачу, наприклад 5.

Не потрібно завчати визначення. Візьміть одне слово й поясніть його на прикладі нашого помічника. Запишіть у нотатках власне речення. Англійську назву залишено, щоб ви впізнали її в документації.

Розрахунок крок за кроком

За межі 5 кроків шостий виклик відхиляється.

Пошук → калькулятор → відповідь має два виклики інструментів. Пошук → пошук → ... може не наближати результат. Ліміт зупиняє витрати, але не гарантує розумний план: записуйте дії та їхні результати.

Спробуйте змінити одне число

Повторіть розрахунок на аркуші або в Python. Спочатку передбачте результат, потім перевірте. Важливо розуміти, що саме вимірює число: схожість, правильність, пам’ять чи час. Не всі ці показники можна порівнювати між собою.

Як з’єднані частини

Одна точка виконання

dispatch() завжди перевіряє назву. Жоден запропонований виклик не має обходити цей шлях.

Пройдіть шлях одного питання

Уявіть питання «Як підключити VPN?». Для кожного блока схеми скажіть: що він отримує, що робить і що передає далі. Потім повторіть для неправильного вводу. Так ви зрозумієте, де виникає помилка, замість шукати її в усьому проєкті одразу.

Корисні звички та їхня ціна

Почніть без зовнішніх змін

Калькулятор і читання документів простіше перевіряти, ніж видалення чи надсилання.

Перевіряйте типи

add приймає рівно два числа. True у Python схожий на 1, але тут не є дозволеним числом.

Підтвердження людини

Перед реальною зміною покажіть точну дію й отримайте дозвіл.

У кожної зручності є ціна. Додатковий пошук займає час, збереження даних потребує місця, перевірки додають код. Оберіть одну пораду й поясніть, від якої конкретної помилки вона захищає.

Типові помилки й виправлення

eval для зручності

Текст може виконати сторонній код; дозволених функцій достатньо.

Вгадати невідому назву

Краще відхилити, ніж виконати іншу дію.

Цикл без межі

Агент може повторювати ту саму невдачу.

Як розібрати помилку

Оберіть один випадок і відтворіть його на своїх навчальних даних. Запишіть три речі: що очікували, що отримали та чому. Виправте причину й повторіть той самий випадок. Додайте перевірку, щоб помилка не повернулася після наступної зміни.

Код: запускаємо та розбираємо

  1. Знайдіть TOOLS.
  2. Перевірте add() на числах.
  3. Викличте dispatch() з add.
  4. Передайте неправильну назву й типи.
  5. Перевірте execute() із завеликим списком.
Завантажити 11.py — код і перевірки ↓

Збережіть файл у новій папці. Приклад працює на Python 3.12+ зі стандартною бібліотекою, без платних сервісів. Нижче його основна частина; спочатку розберемо, що роблять функції.

"""Run: python 11.py. Allowlisted tools, no eval, no external effects."""
import math
import unittest

def finite_number(value):
    return type(value) in (int, float) and math.isfinite(value)

def add(args):
    if not isinstance(args, dict) or set(args) != {'a', 'b'} or not all(finite_number(v) for v in args.values()):
        raise ValueError('Require finite a and b')
    result = args['a'] + args['b']
    if not finite_number(result):
        raise ValueError('Result overflow')
    return result

TOOLS = {'add': add}

def dispatch(name, args):
    if name not in TOOLS:
        raise ValueError('Tool not allowed')
    return TOOLS[name](args)

def execute(calls, limit=5):
    if limit < 1 or len(calls) > limit:
        raise ValueError('Step limit exceeded')
    return [dispatch(call['name'], call['args']) for call in calls]

Що тут відбувається

  • dispatch() шукає функцію у словнику, а не читає текст як код.
  • add() перевіряє поля й типи до обчислення.
  • execute() виконує готові команди, це ще не повний агент із моделлю.

Маленький запуск із відомим результатом

Створіть demo.py у тій самій папці, де лежить 11.py. Скопіюйте наступний код і виконайте python demo.py. runpy.run_path() завантажує функції зі збереженого файла; ви не повинні переписувати їх вручну.

import runpy
m = runpy.run_path("11.py")
print(m["dispatch"]("add", {"a": 127, "b": 386}))

Перевірки та обробка помилок

У завантаженому файлі вже є перевірки. Виконайте python 11.py з його папки. Наприкінці має бути OK. Це означає, що перевірки прикладу пройшли, а не що весь майбутній помічник готовий.

class Tests(unittest.TestCase):
    def test_allowed(self):
        self.assertEqual(execute([{'name': 'add', 'args': {'a': 2, 'b': 3}}]), [5])
    def test_policy(self):
        with self.assertRaises(ValueError):
            dispatch('shell', {})
        for args in [{'a': True, 'b': 1}, {'a': math.nan, 'b': 1}, {'a': 1, 'b': 2, 'extra': 0}]:
            with self.assertRaises(ValueError):
                dispatch('add', args)
        with self.assertRaises(ValueError):
            execute([{}]*6)

if __name__ == '__main__':
    unittest.main()

assertEqual перевіряє рівність, assertTrue — істинність умови, assertRaises — очікувану помилку. Якщо перевірка не пройшла, прочитайте очікуване й отримане значення. Помилка на неправильному вводі часто є саме потрібною поведінкою.

Підміна зовнішнього сервісу перевіряє ваш код без мережі. Якість справжньої моделі, роботу зовнішньої бази та швидкість на вашому обладнанні перевіряють окремо. У FastAPI перетворюйте очікувані помилки на зрозумілу відповідь користувачу.

Практика: зробіть самостійно

Побудуйте контрольовані інструменти: спочатку додавання, потім пошук.

Кроки завдання

  1. Опишіть add і пошук у власних документах.
  2. Запишіть поля й типи кожного.
  3. Додайте пошук у registry із перевіркою аргументів.
  4. Підготуйте 5 списків команд, включно з неправильною назвою та типом.
  5. Перевірте межу 5 кроків на списку з 6.
  6. Додатково підключіть модель-пропонувача, лишивши перевірки у Python.

Що показати після виконання

  • Словник функцій.
  • П’ять послідовностей і результати.
  • Перевірки відхилення.
Почніть із мінімального варіанта. Частини з позначкою «додатково» не потрібні для першого успіху. Якщо зовнішня модель чи обладнання недоступні, виконайте незалежні кроки й запишіть, що саме ще не перевіряли.

Як перевірити свою роботу

Що перевірити кодом

  • 127 + 386 = 513.
  • Невідома функція не виконується.
  • Неправильні аргументи й зайві кроки відхиляються.

Що перевірити своїми очима

  • Модель не обходить перевірку.
  • Послідовність дій видно у звіті.
  • Зовнішніх змін без підтвердження немає.
