Як дати моделі зрозуміле завдання

Після цього розділу ви зможете

Написати інструкцію для сортування звернень і перевірити потрібний формат відповіді.

Промпт — текст завдання для моделі. «Розбери звернення» незрозуміло. Краще: «Визнач категорію: billing — оплата, support — технічна проблема, other — решта. Поверни лише JSON із полем category». Це схоже на завдання колезі: поясніть результат, який очікуєте.

Вам достатньо базового Python: функцій, списків, словників та винятків. Працюємо над одним помічником для інструкцій команди. Спочатку прочитайте приклад, потім запустіть маленький код, після цього виконайте власне завдання. Незрозуміле слово шукайте на сторінці «Нові слова простими словами».

Як це працює на прикладі

Приклади уточнюють правила: «Списали гроші двічі» → billing; «Не можу зайти» → support. Для «Після оплати немає доступу» можливі різні трактування. Спочатку оберіть правило й покажіть у промпті, а не сподівайтеся, що модель вгадає вашу домовленість.

Після відповіді Python читає JSON і перевіряє поля. Правильний формат не гарантує зміст: {"category":"billing"} — коректний JSON, але неправильна категорія для забутого пароля. Тому формат і правильність класифікації перевіряйте окремо.

Завдання без готових прикладів відповіді.

Завдання з кількома парами «вхід → відповідь».

Перевірка структури та значень. JSON — текстовий формат для словників і списків.

Спробуйте змінити одне число

Повторіть розрахунок на аркуші або в Python. Спочатку передбачте результат, потім перевірте. Важливо розуміти, що саме вимірює число: схожість, правильність, пам’ять чи час. Не всі ці показники можна порівнювати між собою.

Як з’єднані частини

Пропозиція й перевірка

Модель пропонує категорію, сервер приймає тільки дозволений формат. Текст відповіді не виконується як код.

Пройдіть шлях одного питання

Уявіть питання «Як підключити VPN?». Для кожного блока схеми скажіть: що він отримує, що робить і що передає далі. Потім повторіть для неправильного вводу. Так ви зрозумієте, де виникає помилка, замість шукати її в усьому проєкті одразу.

Завантажити 04.py — код і перевірки ↓

Збережіть файл у новій папці. Приклад працює на Python 3.12+ зі стандартною бібліотекою, без платних сервісів. Нижче його основна частина; спочатку розберемо, що роблять функції.

"""Run: python 04.py. Parse/validate only; no inference accuracy claim."""
import json
import unittest

CATEGORIES = {'billing', 'support', 'other'}

def parse_result(raw):
    try:
        value = json.loads(raw)
    except (TypeError, json.JSONDecodeError) as error:
        raise ValueError('Invalid JSON') from error
    if not isinstance(value, dict) or set(value) != {'category'}:
        raise ValueError('Expected exactly category')
    if not isinstance(value['category'], str) or value['category'] not in CATEGORIES:
        raise ValueError('Unknown category')
    return value['category']

Що тут відбувається

  • json.loads() перетворює текст на Python-значення.
  • set(value) перевіряє назви полів: дозволено лише category.
  • CATEGORIES обмежує значення трьома відомими словами.

Маленький запуск із відомим результатом

Створіть demo.py у тій самій папці, де лежить 04.py. Скопіюйте наступний код і виконайте python demo.py. runpy.run_path() завантажує функції зі збереженого файла; ви не повинні переписувати їх вручну.

import runpy
m = runpy.run_path("04.py")
print(m["parse_result"]('{"category":"support"}'))

Очікуваний результат

support

Перевірки та обробка помилок

У завантаженому файлі вже є перевірки. Виконайте python 04.py з його папки. Наприкінці має бути OK. Це означає, що перевірки прикладу пройшли, а не що весь майбутній помічник готовий.

class Tests(unittest.TestCase):
    def test_valid(self):
        self.assertEqual(parse_result('{"category":"support"}'), 'support')
    def test_invalid(self):
        for raw in ['not JSON', '[]', '{}', '{"category":"unknown"}', '{"category":"support","extra":1}', '{"category":[]}']:
            with self.assertRaises(ValueError):
                parse_result(raw)

if __name__ == '__main__':
    unittest.main()

assertEqual перевіряє рівність, assertTrue — істинність умови, assertRaises — очікувану помилку. Якщо перевірка не пройшла, прочитайте очікуване й отримане значення. Помилка на неправильному вводі часто є саме потрібною поведінкою.

Підміна зовнішнього сервісу перевіряє ваш код без мережі. Якість справжньої моделі, роботу зовнішньої бази та швидкість на вашому обладнанні перевіряють окремо. У FastAPI перетворюйте очікувані помилки на зрозумілу відповідь користувачу.

Практика: зробіть самостійно

Створіть сортувальник звернень. Без підключеної моделі почніть із перевірки готових відповідей.

Кроки завдання

  1. Напишіть 12 звернень і вручну поставте категорії.
  2. Відкладіть 4 до фінальної перевірки.
  3. На решті порівняйте дві інструкції, якщо є доступ до моделі.
  4. Пропустіть відповіді через parse_result().
  5. Окремо порахуйте правильний формат та категорії.
  6. Перевірте відкладені звернення; без моделі позначте якість класифікації як невиміряну.

Що показати після виконання

  • Два промпти.
  • Таблиця звернень і результатів.
  • Перевірки неправильного JSON.
Почніть із мінімального варіанта. Частини з позначкою «додатково» не потрібні для першого успіху. Якщо зовнішня модель чи обладнання недоступні, виконайте незалежні кроки й запишіть, що саме ще не перевіряли.

Як перевірити свою роботу

Що перевірити кодом

  • Дозволена категорія приймається.
  • Зайві поля відхиляються.
  • Неправильний JSON повертає ValueError.

Що перевірити своїми очима

  • Правило для неоднозначних звернень записане.
  • Відкладені приклади не використані під час редагування.
  • Зміст і формат оцінені окремо.
