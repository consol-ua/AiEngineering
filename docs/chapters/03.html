Як мовна модель створює текст

Після цього розділу ви зможете

Пояснити токени й контекст та побачити, як температура змінює вибір продовження.

Після «Столиця України —» модель оцінює можливі продовження й обирає наступну частину тексту. Додає її до вхідного тексту й повторює процес. Навчання на багатьох прикладах дозволяє писати зв’язно, але не гарантує правильність кожного факту. Впевнене формулювання не замінює джерело.

Вам достатньо базового Python: функцій, списків, словників та винятків. Працюємо над одним помічником для інструкцій команди. Спочатку прочитайте приклад, потім запустіть маленький код, після цього виконайте власне завдання. Незрозуміле слово шукайте на сторінці «Нові слова простими словами».

Як це працює на прикладі

Текст розбивають на токени: слова, частини слів або знаки. Точне розбиття залежить від моделі. Довга українська назва може мати кілька токенів. Контекст — текст, доступний за поточний виклик: інструкція, питання, історія та документи. Модель має межу його розміру; треба також залишити місце для відповіді.

Temperature, або температура, змінює різноманітність вибору. Менша температура зазвичай зосереджує вибір на найвищих оцінках, більша робить його рівнішим. Це не регулятор правдивості: низька температура може стабільно повторювати помилку. Нижче розберемо два вигадані числові варіанти, а не справжню LLM.

Нові слова простими словами

Токен
Одиниця тексту для моделі. Кількість токенів не обов’язково збігається зі словами.
Контекст
Усе, що модель бачить у поточному виклику. Попередня розмова доступна лише якщо її передали.
Attention — увага
Механізм зв’язків між частинами тексту. Наприклад, з яким іменником пов’язане «вона».
Галюцинація
Правдоподібний, але хибний або непідтверджений текст, наприклад вигадане посилання.

Не потрібно завчати визначення. Візьміть одне слово й поясніть його на прикладі нашого помічника. Запишіть у нотатках власне речення. Англійську назву залишено, щоб ви впізнали її в документації.

Розрахунок крок за кроком

Місце для документів = межа контексту − інструкція − питання − історія − запас відповіді.

Умовна межа 1000 токенів: інструкція 100, питання 50, історія 200, відповідь 250. Документам лишається 1000−100−50−200−250=400. Реальні межі дивіться в описі моделі; ці числа лише навчальні.

Спробуйте змінити одне число

Повторіть розрахунок на аркуші або в Python. Спочатку передбачте результат, потім перевірте. Важливо розуміти, що саме вимірює число: схожість, правильність, пам’ять чи час. Не всі ці показники можна порівнювати між собою.

Код: запускаємо та розбираємо

  1. Знайдіть logits — оцінки варіантів до перетворення на ймовірності.
  2. Передайте [2, 1] у softmax().
  3. Порівняйте температури 0,5 та 2.
  4. Перевірте, що сума ймовірностей близько 1.
Завантажити 03.py — код і перевірки ↓

Збережіть файл у новій папці. Приклад працює на Python 3.12+ зі стандартною бібліотекою, без платних сервісів. Нижче його основна частина; спочатку розберемо, що роблять функції.

"""Run: python 03.py. Toy logits; this is not an LLM/tokenizer."""
import math
import unittest

def softmax(logits, temperature=1.0):
    if not math.isfinite(temperature) or temperature <= 0:
        raise ValueError('Positive finite temperature required')
    if not logits or any(not math.isfinite(x) for x in logits):
        raise ValueError('Finite nonempty logits required')
    maximum = max(logits)
    weights = [math.exp((x - maximum) / temperature) for x in logits]
    total = math.fsum(weights)
    return [x / total for x in weights]

Що тут відбувається

  • softmax() перетворює оцінки на додатні ймовірності із сумою 1.
  • За нижчої температури перший варіант має близько 88%, за вищої — 62%.
  • Це не вимірювання правдивості моделі, а маленький приклад вибору.

Маленький запуск із відомим результатом

Створіть demo.py у тій самій папці, де лежить 03.py. Скопіюйте наступний код і виконайте python demo.py. runpy.run_path() завантажує функції зі збереженого файла; ви не повинні переписувати їх вручну.

import runpy
m = runpy.run_path("03.py")
for t in [0.5, 2]:
    print(t, [round(x, 3) for x in m["softmax"]([2, 1], t)])

0.5 [0.881, 0.119]
2 [0.622, 0.378]

Передайте [1, 1] і передбачте дві ймовірності. Спробуйте температуру 0: наша функція її відхиляє.

Перевірки та обробка помилок

У завантаженому файлі вже є перевірки. Виконайте python 03.py з його папки. Наприкінці має бути OK. Це означає, що перевірки прикладу пройшли, а не що весь майбутній помічник готовий.

class Tests(unittest.TestCase):
    def test_distribution(self):
        values = softmax([1000, 999])
        self.assertAlmostEqual(sum(values), 1)
        self.assertAlmostEqual(values[0], 0.7310585786)
        self.assertGreater(softmax([2, 1], 0.5)[0], softmax([2, 1], 1)[0])
    def test_invalid(self):
        for logits, temperature in [([], 1), ([1], 0), ([1], -1), ([math.nan], 1), ([1], math.inf)]:
            with self.assertRaises(ValueError):
                softmax(logits, temperature)

if __name__ == '__main__':
    unittest.main()

assertEqual перевіряє рівність, assertTrue — істинність умови, assertRaises — очікувану помилку. Якщо перевірка не пройшла, прочитайте очікуване й отримане значення. Помилка на неправильному вводі часто є саме потрібною поведінкою.

Підміна зовнішнього сервісу перевіряє ваш код без мережі. Якість справжньої моделі, роботу зовнішньої бази та швидкість на вашому обладнанні перевіряють окремо. У FastAPI перетворюйте очікувані помилки на зрозумілу відповідь користувачу.

Практика: зробіть самостійно

Дослідіть розбиття тексту на токени. Модель завантажувати не потрібно, достатньо tokenizer — програми розбиття.

Кроки завдання

  1. Напишіть 5 українських та 5 англійських фраз.
  2. Виберіть tokenizer публічної моделі з Hugging Face.
  3. За офіційним прикладом Transformers завантажте AutoTokenizer.from_pretrained(). Потрібна мережа.
  4. Запишіть символи, слова й кількість tokenizer.encode() для кожної фрази.
  5. Додайте URL та рядок коду; порівняйте.
  6. Якщо завантаження недоступне, виконайте числову частину й позначте tokenizer як не перевірений.

Що показати після виконання

  • Таблиця текстів із назвою tokenizer.
  • Два розподіли ймовірностей.
  • Розрахунок контексту.
Почніть із мінімального варіанта. Частини з позначкою «додатково» не потрібні для першого успіху. Якщо зовнішня модель чи обладнання недоступні, виконайте незалежні кроки й запишіть, що саме ще не перевіряли.

Як перевірити свою роботу

Що перевірити кодом

  • Сума softmax() приблизно 1.
  • Неправильна температура відхиляється.
  • У таблиці вказана конкретна модель tokenizer.

Що перевірити своїми очима

  • Відрізняю слово й токен.
  • Не роблю висновок про правдивість за температурою.
  • Залишив місце для відповіді.
