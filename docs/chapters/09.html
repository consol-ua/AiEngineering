Як покращити пошук у документах

Після цього розділу ви зможете

Змінити одну настройку пошуку й перевірити на тих самих питаннях, чи стало краще.

Інструкція каже «Встановіть VPN-клієнт. Потім увімкніть другий фактор». Якщо розрізати між реченнями, помічник може отримати лише половину. Надто великий фрагмент теж незручний: передає зайвий текст. Розмір перевіряйте на своїх документах, а не шукайте універсальне число.

Вам достатньо базового Python: функцій, списків, словників та винятків. Працюємо над одним помічником для інструкцій команди. Спочатку прочитайте приклад, потім запустіть маленький код, після цього виконайте власне завдання. Незрозуміле слово шукайте на сторінці «Нові слова простими словами».

Як це працює на прикладі

Overlap — перекриття: кінець одного фрагмента повторюється на початку іншого, щоб не загубити зв’язок. Наприклад, "abcd", "defg", "gh". Повтор збільшує обсяг даних, тому він не має бути надмірним. Якщо перекриття дорівнює розміру, розбиття взагалі не просунеться.

Hybrid search поєднує пошук слів і змісту. RRF об’єднує списки за позиціями документів, коли оцінки різних способів не можна прямо порівняти. Reranking — додаткова оцінка вже знайдених кандидатів, щоб підняти найкорисніших. У нашому коді є об’єднання списків, але не модель reranking.

Розрахунок крок за кроком

Крок розбиття = розмір − перекриття; крок має бути більшим за 0.

Розмір 4, перекриття 1: крок 3. Починаємо з позицій 0, 3, 6. Для abcdefgh маємо abcd, defg, gh. Перекриття 4 дало б нульовий крок, тому код його відхиляє.

Спробуйте змінити одне число

Повторіть розрахунок на аркуші або в Python. Спочатку передбачте результат, потім перевірте. Важливо розуміти, що саме вимірює число: схожість, правильність, пам’ять чи час. Не всі ці показники можна порівнювати між собою.

Завантажити 09.py — код і перевірки ↓

Збережіть файл у новій папці. Приклад працює на Python 3.12+ зі стандартною бібліотекою, без платних сервісів. Нижче його основна частина; спочатку розберемо, що роблять функції.

"""Run: python 09.py. Character splitter and rank fusion baseline."""
import unittest

def split(text, size=100, overlap=20):
    if size <= 0 or overlap < 0 or overlap >= size:
        raise ValueError('Require 0 <= overlap < size')
    output = []
    start = 0
    while start < len(text):
        output.append(text[start:start+size])
        if start + size >= len(text):
            break
        start += size - overlap
    return output

def rrf(lists, c=60):
    if c < 0:
        raise ValueError('Nonnegative smoothing required')
    scores = {}
    for ranking in lists:
        seen = set()
        for rank, id in enumerate(ranking, 1):
            if id in seen:
                raise ValueError('Duplicate ID in ranking')
            seen.add(id)
            scores[id] = scores.get(id, 0) + 1 / (c + rank)
    return sorted(scores.items(), key=lambda x: (-x[1], x[0]))

Що тут відбувається

  • start збільшується на size − overlap.
  • leave є в обох списках і в цьому прикладі отримує найбільше балів.
  • Це приклад об’єднання, а не доказ, що leave відповідає на конкретне питання.

Перевірки та обробка помилок

У завантаженому файлі вже є перевірки. Виконайте python 09.py з його папки. Наприкінці має бути OK. Це означає, що перевірки прикладу пройшли, а не що весь майбутній помічник готовий.

class Tests(unittest.TestCase):
    def test_coverage(self):
        self.assertEqual(split('abcdefgh', 4, 1), ['abcd', 'defg', 'gh'])
        with self.assertRaises(ValueError):
            split('abc', 4, 4)
    def test_fusion(self):
        result = rrf([['a', 'b'], ['b', 'c']])
        self.assertEqual(result[0][0], 'b')
        self.assertEqual(len(result), 3)
        with self.assertRaises(ValueError):
            rrf([['a', 'a']])

if __name__ == '__main__':
    unittest.main()

assertEqual перевіряє рівність, assertTrue — істинність умови, assertRaises — очікувану помилку. Якщо перевірка не пройшла, прочитайте очікуване й отримане значення. Помилка на неправильному вводі часто є саме потрібною поведінкою.

Підміна зовнішнього сервісу перевіряє ваш код без мережі. Якість справжньої моделі, роботу зовнішньої бази та швидкість на вашому обладнанні перевіряють окремо. У FastAPI перетворюйте очікувані помилки на зрозумілу відповідь користувачу.

Кроки завдання

  1. Залиште ті самі документи й 8 питань.

Як перевірити свою роботу

Що перевірити кодом

  • Фрагменти не довші за size.
  • Неправильне перекриття відхиляється.
  • Об’єднаний список не дублює id.

Що перевірити своїми очима

  • Уривки зберігають умови інструкції.
  • Питання однакові в обох запусках.
  • Відрізняю RRF від reranking моделлю.
