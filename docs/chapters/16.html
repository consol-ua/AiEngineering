Після цього розділу ви зможете

Об’єднати частини та показати іншій людині можливості, відмови й запуск.

Обирайте невелику базу інструкцій однієї команди або продукту. Ви вже маєте перевірку питання, документи, пошук, модель, джерела й журнал. З’єднайте їх у зрозумілий шлях. Якщо одного пошуку вистачає, складний агент не обов’язковий.

Як це працює на прикладі

Готовність — конкретні перевірені умови: потрібні джерела знаходяться, чужі дані не видаються, записи переживають перезапуск, інша людина запускає за README. Пороги обирають до перевірки. Числа нашої функції перевірки — навчальна політика, а не універсальні правила всіх продуктів.

Демо має включати успіх, питання поза базою, збій моделі та збережені дані. Запишіть обмеження, наприклад непідтримувану мову чи пропуск умов інструкції. Статуси «пройдено», «не пройдено» й «ще не запускали» допомагають чесно планувати покращення.

Нові слова простими словами

Критерій готовності
Умова перед випуском, наприклад перевірені права доступу.
Звіт версії
Який код, документи, модель і настройки перевіряли та з яким результатом.
Відоме обмеження
Ситуація, яку помічник не підтримує або ще не перевіряли.
Чистий запуск
Запуск у новому середовищі за README без випадкових старих налаштувань.

Не потрібно завчати визначення. Візьміть одне слово й поясніть його на прикладі нашого помічника. Запишіть у нотатках власне речення. Англійську назву залишено, щоб ви впізнали її в документації.

Розрахунок крок за кроком

Готовність = якість перевірена І права перевірені І запуск повторюється І дані відновлюються.

У навчальному gate: 30 питань, Recall@3≥0,8, p95≤5000 ms та нуль витоків. Один витік блокує навіть Recall@3=0,99. Невиміряний час не стає добрим автоматично. Відновлення копії перевірте окремо: release_gate() його не містить.

Спробуйте змінити одне число

Повторіть розрахунок на аркуші або в Python. Спочатку передбачте результат, потім перевірте. Важливо розуміти, що саме вимірює число: схожість, правильність, пам’ять чи час. Не всі ці показники можна порівнювати між собою.

Завантажити 16.py — код і перевірки ↓

Збережіть файл у новій папці. Приклад працює на Python 3.12+ зі стандартною бібліотекою, без платних сервісів. Нижче його основна частина; спочатку розберемо, що роблять функції.

"""Run: python 16.py. Illustrative thresholds, not production policy."""
import math
import unittest

POLICY = {'min_questions': 30, 'min_recall': 0.8, 'max_p95_ms': 5000}

def release_gate(report):
    reasons = []
    for key in ['questions', 'recall_at_3', 'p95_ms', 'tenant_leaks', 'clean_start_verified']:
        if key not in report:
            reasons.append('Missing: ' + key)
    if reasons:
        return {'ready': False, 'reasons': reasons}
    for key in ['questions', 'recall_at_3', 'p95_ms', 'tenant_leaks']:
        if type(report[key]) not in (int, float) or not math.isfinite(report[key]) or report[key] < 0:
            reasons.append('Invalid metric: ' + key)
    if reasons:
        return {'ready': False, 'reasons': reasons}
    if report['questions'] < POLICY['min_questions']:
        reasons.append('Insufficient evaluation questions')
    if not POLICY['min_recall'] <= report['recall_at_3'] <= 1:
        reasons.append('Retrieval quality gate failed')
    if report['p95_ms'] > POLICY['max_p95_ms']:
        reasons.append('Latency gate failed')
    if report['tenant_leaks'] != 0:
        reasons.append('Critical tenant leak')
    if report['clean_start_verified'] is not True:
        reasons.append('Clean start unverified')
    return {'ready': not reasons, 'reasons': reasons}

Що тут відбувається

  • Числа тут задані вручну. True показує роботу умов, не реальну якість вашого помічника.
  • Для свого рішення підставте результати вимірів.
  • reasons містить усі причини, що блокують готовність.

Маленький запуск із відомим результатом

Створіть demo.py у тій самій папці, де лежить 16.py. Скопіюйте наступний код і виконайте python demo.py. runpy.run_path() завантажує функції зі збереженого файла; ви не повинні переписувати їх вручну.

import runpy
m = runpy.run_path("16.py")
r = m["release_gate"]({"questions": 30, "recall_at_3": 0.9,
    "p95_ms": 1000, "tenant_leaks": 0, "clean_start_verified": True})
print(r)

Очікуваний результат

{'ready': True, 'reasons': []}

Змініть і перевірте

Поставте tenant_leaks=1: очікуйте ready=False. Потім приберіть p95_ms й прочитайте причину.

Перевірки та обробка помилок

У завантаженому файлі вже є перевірки. Виконайте python 16.py з його папки. Наприкінці має бути OK. Це означає, що перевірки прикладу пройшли, а не що весь майбутній помічник готовий.

class Tests(unittest.TestCase):
    def test_ready(self):
        self.assertTrue(release_gate({'questions': 30, 'recall_at_3': 0.9, 'p95_ms': 1000, 'tenant_leaks': 0, 'clean_start_verified': True})['ready'])
    def test_missing_and_critical(self):
        self.assertFalse(release_gate({})['ready'])
        value = {'questions': 30, 'recall_at_3': 0.99, 'p95_ms': 10, 'tenant_leaks': 1, 'clean_start_verified': True}
        self.assertIn('Critical tenant leak', release_gate(value)['reasons'])
        value['tenant_leaks'] = 0
        value['p95_ms'] = math.nan
        self.assertFalse(release_gate(value)['ready'])

if __name__ == '__main__':
    unittest.main()

assertEqual перевіряє рівність, assertTrue — істинність умови, assertRaises — очікувану помилку. Якщо перевірка не пройшла, прочитайте очікуване й отримане значення. Помилка на неправильному вводі часто є саме потрібною поведінкою.

Підміна зовнішнього сервісу перевіряє ваш код без мережі. Якість справжньої моделі, роботу зовнішньої бази та швидкість на вашому обладнанні перевіряють окремо. У FastAPI перетворюйте очікувані помилки на зрозумілу відповідь користувачу.

Практика: зробіть самостійно

Побудуйте помічника для власних інструкцій. Почніть з 3 файлів і 5 питань, потім розширте.

Кроки завдання

  1. Оберіть тему, користувача й 10–20 файлів.
  2. Підключіть вхід та дозволені документи.
  3. Додайте джерела, відмову й обмежене очікування.
  4. Підготуйте 30 питань: звичайні, поза базою й спроби доступу до чужого.
  5. Зберіть звіт, перевірте перезапуск і відновлення.
  6. Напишіть README й покажіть 5-хвилинне демо з невдалими сценаріями.

Що показати після виконання

  • Проєкт і README.
  • 30 питань та всі результати.
  • Схема, перевірка копії та обмеження.
Почніть із мінімального варіанта. Частини з позначкою «додатково» не потрібні для першого успіху. Якщо зовнішня модель чи обладнання недоступні, виконайте незалежні кроки й запишіть, що саме ще не перевіряли.

Як перевірити свою роботу

Що перевірити кодом

  • Gate відхиляє відсутні виміри й витоки.
  • /ask працює після чистого запуску.
  • Звіт містить не виконані перевірки.

Що перевірити своїми очима

  • Факти можна перевірити за джерелом.
  • Інша людина повторює запуск.
  • Демо показує межі й помилки.

Як зрозуміти, що завдання виконане

Можу пояснитиПеревірив неправильний випадок, пояснив причину та записав обмеження.
