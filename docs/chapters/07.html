Де зберігати вектори й документи

Після цього розділу ви зможете

Зберегти записи, перевірити перезапуск і навчитися оновлювати без дублікатів.

Список у пам’яті зникне після завершення Python. Нам потрібна база. Запис має id, текст, вектор та власника: наприклад, vpn-1, «Встановіть VPN», команда A. Сталий id дозволяє оновити саме цей документ, а не додати випадкову копію.

Вам достатньо базового Python: функцій, списків, словників та винятків. Працюємо над одним помічником для інструкцій команди. Спочатку прочитайте приклад, потім запустіть маленький код, після цього виконайте власне завдання. Незрозуміле слово шукайте на сторінці «Нові слова простими словами».

РОЗДІЛ 07 · НАВЧАЛЬНА СТОРІНКА 2/12

Як це працює на прикладі

Векторна база прискорює пошук близьких векторів. Почнемо з SQLite: збережемо список чисел як JSON і навчимося додавати, змінювати й видаляти. Цей приклад не є спеціалізованим швидким векторним пошуком. Після перевірки життєвого циклу можна перенести дані в Chroma.

Команди A та B можуть мати документи з однаковим id. Їх розрізняє власник. Документ B не має потрапити у відповідь A, навіть якщо він найсхожіший. Власника беріть із перевіреного входу, а не довільного поля запиту. Видалення теж обмежуйте командою.

Нові слова простими словами

Метадані
Дані про документ: id, джерело, власник і версія.
Tenant
Команда-власник даних. У прикладі це A або B.
Upsert
Додати, якщо запису немає; оновити, якщо він існує.
Індекс
Допоміжна структура для швидшого пошуку. Наближений пошук може пропускати кандидата, тому якість перевіряють.

Не потрібно завчати визначення. Візьміть одне слово й поясніть його на прикладі нашого помічника. Запишіть у нотатках власне речення. Англійську назву залишено, щоб ви впізнали її в документації.

Розрахунок крок за кроком

Місце для векторів ≈ записи × координати × байти на число.

1000 векторів по 384 числа у float32, тобто 4 байти: 1000×384×4 = 1 536 000 байтів, близько 1,5 MB. Текст, метадані й індекс займають додаткове місце.

Спробуйте змінити одне число

Повторіть розрахунок на аркуші або в Python. Спочатку передбачте результат, потім перевірте. Важливо розуміти, що саме вимірює число: схожість, правильність, пам’ять чи час. Не всі ці показники можна порівнювати між собою.

Як з’єднані частини

Id разом із власником

Пара (tenant, id) визначає запис. Так однаковий id у різних команд не змішує дані.

Пройдіть шлях одного питання

Уявіть питання «Як підключити VPN?». Для кожного блока схеми скажіть: що він отримує, що робить і що передає далі. Потім повторіть для неправильного вводу. Так ви зрозумієте, де виникає помилка, замість шукати її в усьому проєкті одразу.

Типові помилки й виправлення

Без запису на диск

Зміни можуть не пережити закриття без commit().

Видалити лише текст

Старий вектор або фрагмент може лишитися в пошуку.

Права лише на екрані

Модель уже могла побачити чужий текст. Обмежуйте читання раніше.

Як розібрати помилку

Оберіть один випадок і відтворіть його на своїх навчальних даних. Запишіть три речі: що очікували, що отримали та чому. Виправте причину й повторіть той самий випадок. Додайте перевірку, щоб помилка не повернулася після наступної зміни.

Завантажити 07.py — код і перевірки ↓

Збережіть файл у новій папці. Приклад працює на Python 3.12+ зі стандартною бібліотекою, без платних сервісів. Нижче його основна частина; спочатку розберемо, що роблять функції.

"""Run: python 07.py. SQLite lifecycle baseline; not an ANN database."""
import json
import sqlite3
import tempfile
from pathlib import Path
import unittest

class Store:
    def __init__(self, path):
        self.db = sqlite3.connect(path)
        self.db.execute('CREATE TABLE IF NOT EXISTS chunks(tenant TEXT,id TEXT,text TEXT,vector TEXT,PRIMARY KEY(tenant,id))')
    def upsert(self, tenant, id, text, vector):
        self.db.execute('INSERT INTO chunks VALUES(?,?,?,?) ON CONFLICT(tenant,id) DO UPDATE SET text=excluded.text,vector=excluded.vector', (tenant, id, text, json.dumps(vector)))
        self.db.commit()
    def rows(self, tenant):
        return self.db.execute('SELECT id,text,vector FROM chunks WHERE tenant=? ORDER BY id', (tenant,)).fetchall()
    def delete(self, tenant, id):
        self.db.execute('DELETE FROM chunks WHERE tenant=? AND id=?', (tenant, id))
        self.db.commit()
    def close(self):
        self.db.close()

Що тут відбувається

  • :memory: створює тимчасову базу. Для збереження після перезапуску задайте шлях до файла.
  • Другий upsert() змінює той самий запис, не додає другий.
  • Параметри SQL передані окремо, а не склеєні з текстом запиту.

Маленький запуск із відомим результатом

Створіть demo.py у тій самій папці, де лежить 07.py. Скопіюйте наступний код і виконайте python demo.py. runpy.run_path() завантажує функції зі збереженого файла; ви не повинні переписувати їх вручну.

import runpy
m = runpy.run_path("07.py")
s = m["Store"](":memory:")
s.upsert("A", "vpn", "Старий текст", [1, 0])
s.upsert("A", "vpn", "Новий текст", [1, 0])
print(s.rows("A")[0][1])
print(len(s.rows("A")))
s.close()

Перевірки та обробка помилок

У завантаженому файлі вже є перевірки. Виконайте python 07.py з його папки. Наприкінці має бути OK. Це означає, що перевірки прикладу пройшли, а не що весь майбутній помічник готовий.

class Tests(unittest.TestCase):
    def test_lifecycle_and_isolation(self):
        with tempfile.TemporaryDirectory() as directory:
            path = str(Path(directory) / 'index.db')
            store = Store(path)
            store.upsert('A', '1', 'old', [1, 0])
            store.upsert('A', '1', 'new', [0, 1])
            store.upsert('B', '2', 'private', [1, 1])
            store.close()
            store = Store(path)
            self.assertEqual(len(store.rows('A')), 1)
            self.assertEqual(store.rows('A')[0][1], 'new')
            self.assertNotIn('private', str(store.rows('A')))
            store.delete('A', '1')
            self.assertEqual(store.rows('A'), [])
            self.assertEqual(len(store.rows('B')), 1)
            store.close()

if __name__ == '__main__':
    unittest.main()

assertEqual перевіряє рівність, assertTrue — істинність умови, assertRaises — очікувану помилку. Якщо перевірка не пройшла, прочитайте очікуване й отримане значення. Помилка на неправильному вводі часто є саме потрібною поведінкою.

Підміна зовнішнього сервісу перевіряє ваш код без мережі. Якість справжньої моделі, роботу зовнішньої бази та швидкість на вашому обладнанні перевіряють окремо. У FastAPI перетворюйте очікувані помилки на зрозумілу відповідь користувачу.

Практика: зробіть самостійно

Зробіть сховище документів двох команд. Після основних перевірок додайте спеціалізовану базу за бажанням.

Кроки завдання

  1. Створіть index.db з двома документами для кожної команди.
  2. Оновіть один текст A зі сталим id.
  3. Перевірте, що кількість рядків не збільшилась.
  4. Закрийте, відкрийте й прочитайте новий текст.
  5. Видаліть A/vpn та перевірте B/vpn.
  6. Додатково повторіть операції у Chroma за документацією.

Що показати після виконання

  • Файлова база й скрипт операцій.
  • Id до й після оновлення.
  • Результат перезапуску та видалення.
Почніть із мінімального варіанта. Частини з позначкою «додатково» не потрібні для першого успіху. Якщо зовнішня модель чи обладнання недоступні, виконайте незалежні кроки й запишіть, що саме ще не перевіряли.

Як перевірити свою роботу

Що перевірити кодом

  • Оновлення не дублює запис.
  • Файлова база переживає перезапуск.
  • Видалення A не зачіпає B.

Що перевірити своїми очима

  • Власник отриманий після перевірки входу.
  • Розумію різницю :memory: і файла.
  • Старі фрагменти прибрані.

Як зрозуміти, що завдання виконане

Можу пояснитиПеревірив неправильний випадок, пояснив причину та записав обмеження.
