Пам’ять розмови: що зберігати

Після цього розділу ви зможете

Зберегти дві розмови окремо й обрати частину історії для наступної відповіді.

Олена каже «Я користуюся Windows», потім «Як встановити клієнт?». Без історії незрозуміло, яка система. Програма зберігає старі повідомлення й передає їх із питанням. Пам’ять діалогу — це дані вашого коду, а не прихована нескінченна здатність моделі.

Вам достатньо базового Python: функцій, списків, словників та винятків. Працюємо над одним помічником для інструкцій команди. Спочатку прочитайте приклад, потім запустіть маленький код, після цього виконайте власне завдання. Незрозуміле слово шукайте на сторінці «Нові слова простими словами».

Як це працює на прикладі

У базі може бути 100 повідомлень, а в контекст помістяться останні 10. Sliding window — рухоме вікно останніх повідомлень. Summary — короткий переказ старішої частини. Переказ економить місце, але може загубити умову «тільки Windows», тому його теж перевіряють.

Олена й Іван можуть мати однаковий session="chat-1", але їхні розмови не спільні. Читайте за owner + session. Власник надходить із перевіреного входу; довільне ім’я з запиту дозволило б прочитати чужу історію.

Розрахунок крок за кроком

Місце історії = межа контексту − інструкція − документи − питання − запас відповіді.

Навчальний window() рахує слова: два повідомлення по 2 слова, бюджет 2 — лишається останнє. При бюджеті 1 воно не поміститься цілим: повертаємо []. Для справжньої моделі рахуйте токени, а не слова.

Спробуйте змінити одне число

Повторіть розрахунок на аркуші або в Python. Спочатку передбачте результат, потім перевірте. Важливо розуміти, що саме вимірює число: схожість, правильність, пам’ять чи час. Не всі ці показники можна порівнювати між собою.

Завантажити 12.py — код і перевірки ↓

Збережіть файл у новій папці. Приклад працює на Python 3.12+ зі стандартною бібліотекою, без платних сервісів. Нижче його основна частина; спочатку розберемо, що роблять функції.

"""Run: python 12.py. Word-based budget is a toy; use model tokens in lab."""
import sqlite3
import unittest

class Memory:
    def __init__(self):
        self.db = sqlite3.connect(':memory:')
        self.db.execute('CREATE TABLE messages(id INTEGER PRIMARY KEY,owner TEXT,session TEXT,role TEXT,text TEXT)')
    def append(self, owner, session, role, text):
        if role not in {'user', 'assistant'}:
            raise ValueError('Role not permitted')
        self.db.execute('INSERT INTO messages(owner,session,role,text) VALUES(?,?,?,?)', (owner, session, role, text))
    def read(self, owner, session):
        return self.db.execute('SELECT role,text FROM messages WHERE owner=? AND session=? ORDER BY id', (owner, session)).fetchall()

def window(messages, budget):
    if budget < 0:
        raise ValueError('Invalid budget')
    selected, used = [], 0
    for message in reversed(messages):
        cost = len(message[1].split())
        if used + cost > budget:
            break
        selected.append(message)
        used += cost
    return list(reversed(selected))

Що тут відбувається

  • Memory тут тимчасова :memory:-база. Для постійних записів потрібен файл.
  • read() має два фільтри: owner та session.
  • window() лише обирає повідомлення, не переказує й не видаляє.

Маленький запуск із відомим результатом

Створіть demo.py у тій самій папці, де лежить 12.py. Скопіюйте наступний код і виконайте python demo.py. runpy.run_path() завантажує функції зі збереженого файла; ви не повинні переписувати їх вручну.

Перевірки та обробка помилок

У завантаженому файлі вже є перевірки. Виконайте python 12.py з його папки. Наприкінці має бути OK. Це означає, що перевірки прикладу пройшли, а не що весь майбутній помічник готовий.

class Tests(unittest.TestCase):
    def test_owner_and_order(self):
        memory = Memory()
        memory.append('A', 'same', 'user', 'first')
        memory.append('B', 'same', 'user', 'private')
        memory.append('A', 'same', 'assistant', 'second')
        self.assertEqual(memory.read('A', 'same'), [('user', 'first'), ('assistant', 'second')])
        with self.assertRaises(ValueError):
            memory.append('A', 'same', 'system', 'override')
        memory.db.close()
    def test_budget(self):
        data = [('user', 'one two'), ('assistant', 'three four')]
        self.assertEqual(window(data, 2), [data[1]])
        self.assertEqual(window(data, 1), [])

if __name__ == '__main__':
    unittest.main()

assertEqual перевіряє рівність, assertTrue — істинність умови, assertRaises — очікувану помилку. Якщо перевірка не пройшла, прочитайте очікуване й отримане значення. Помилка на неправильному вводі часто є саме потрібною поведінкою.

Підміна зовнішнього сервісу перевіряє ваш код без мережі. Якість справжньої моделі, роботу зовнішньої бази та швидкість на вашому обладнанні перевіряють окремо. У FastAPI перетворюйте очікувані помилки на зрозумілу відповідь користувачу.

Практика: зробіть самостійно

Перевірте два діалоги й втрату раннього факту після обрізання контексту.

Кроки завдання

  1. Створіть двох власників з однаковим session.
  2. Запишіть Windows для одного й Linux для іншого.
  3. Перевірте читання без чужих повідомлень.
  4. Додайте 5 сторонніх повідомлень і застосуйте мале вікно.
  5. Чи лишився ранній факт? Якщо ні, поясніть наслідок для відповіді.
  6. Додатково порівняйте рухоме вікно з коротким переказом.

Що показати після виконання

  • Схема повідомлень.
  • Два діалоги й перевірки доступу.
  • Історія до й після обмеження.
Почніть із мінімального варіанта. Частини з позначкою «додатково» не потрібні для першого успіху. Якщо зовнішня модель чи обладнання недоступні, виконайте незалежні кроки й запишіть, що саме ще не перевіряли.

Як перевірити свою роботу

Що перевірити кодом

  • Olena не бачить Ivan.
  • Порядок відповідає додаванню.
  • Системна роль користувача відхиляється.

  • Відрізняю базу й контекст.
  • Одиниці бюджету вказані.
  • Перевірив втрату раннього факту.
